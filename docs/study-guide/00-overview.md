# 00 · 项目地图

> 用一张图、一张表、一组场景，让你在 10 分钟内知道这个项目**是什么、能干什么、不能干什么**。

---

## 一句话定位

**一个端到端的安全运营平台**：从 syslog / API 接入开始，经历
**校验 → 异常检测 → 攻击链 CEP → LLM 深度审计 → 独立监督 → 响应执行**
的完整链路，全部在 Docker 化的 Kafka / Flink + FastAPI + React 集群上跑通。

> 它不是单一工具，而是把安全运营中心（SOC）日常工作的"流水线"做成了可一键启动的工程产物。

---

## 与同类方案的差异

| 维度 | 传统 SIEM | 单 LLM Agent | **本平台** |
| :--- | :---: | :---: | :---: |
| 实时流处理 | ✅ 强 | ❌ | ✅ Kafka+Flink，秒级延迟 |
| LLM 审计 | ❌ | ✅ 但易幻觉 | ✅ 4 层 + CAD 监督 + Grounding |
| 工具调用安全 | N/A | ⚠️ 无控制 | ✅ MCP Guard 4 层 |
| 真实响应 | ⚠️ 半自动 | ⚠️ 单次 | ✅ 编排 + 审批 + 回滚 |
| 自我审计 | ❌ | ❌ | ✅ 5 道闸：Guard / CAD / Stabilizer / Grounding / 熔断 |
| 可本地跑通 | ⚠️ 重型 | ✅ | ✅ `docker compose up` 即可 |

## 典型使用场景

### 场景 1 · SOC 日常告警处理

- **流量**：syslog-agent 把防火墙 / WAF / 主机日志推 Kafka → Flink 校验打分 → 命中规则或高分告警 → 推前端 → 运营人员处置 → 响应引擎封禁
- **亮点**：审计链路全闭环，每一步有 `trace_id`，可"从一条告警追到原始日志与执行命令"

### 场景 2 · 邮件 / 钓鱼批量识别

- **流量**：邮件网关 webhook → `/api/phishing` → 7 类检测器（发件人 / 链接 / 附件 / 二维码 / BEC）→ LLM 增强判定 → 工单
- **亮点**：检测器解耦、可插拔

### 场景 3 · 0day 调查

- **流量**：EDR 捕获可疑样本 → sandbox 自动提交 CAPE → 行为分析 + 变体聚类 → 自动生成 MITRE 技术标签 → 推到威胁情报库
- **亮点**：从样本到情报全自动

### 场景 4 · 自我保护

- **流量**：LLM 决定调用 `iptables -I INPUT -s x.x.x.x -j DROP` → MCP Guard 4 层检查（白名单 → 权限 → 参数 → 策略）→ SecurityGuard 审查（意图 / 序列 / 频率）→ 实际 SSH 执行 → 记录 + 可回滚
- **亮点**：LLM 不会被诱导去执行危险命令

## 它**不**做的事

诚实标注边界，避免被现场问倒：

- ❌ **不是真实告警源**：内置 `log_simulator.py` 是合成数据；真实部署要对接 syslog / EDR / 防火墙
- ❌ **不内置 ML 训练**：异常评分是规则 / 统计式，不跑深度学习
- ❌ **不是分布式追踪产品**：`trace_id` 自建简单版，不替代 OpenTelemetry 完整能力
- ❌ **不做数据可视化大盘**：前端是功能页，不替代 Grafana / Kibana
- ❌ **NDR / EDR / 沙箱是"可对接"而非"内置"**：CAPE、TAXII、MISP 是外部依赖，开关默认关闭
- ❌ **不替代专业 SIEM**：Splunk / Elastic 在超大规模检索上仍更强，本平台胜在"AI 原生 + 自审计"

## 三个关键设计取舍

> 读源码前先了解这三个判断，能省下很多"为什么要这样写"的困惑。

### 取舍 1 · 用 Kafka / Flink 而非直连 HTTP

**理由**：解耦数据源与处理引擎、支持重放、支持横向扩展、CEP 攻击链只能用流式处理。
**代价**：部署复杂、需要懂 Java。

### 取舍 2 · 把 LLM 拆成 4 层 + CAD

**理由**：单次 LLM 调用幻觉率高，无法审计。拆成 Decomposer → ToolBuilder → Executor → Reviewer 后，每层都有产物可校验；CAD 不信任 LLM 汇报，直接去查底层事件。

### 取舍 3 · 自建 MCP Guard 4 层而非用现成框架

**理由**：现成 MCP 框架只解决"协议标准"，不解决"该不该让 Agent 调这个工具"。我们再加 4 层（白名单 → RBAC → 参数 → 策略）才能在生产用。

1. **跑一遍**：在仓库根执行 `docker compose up -d --build`，等容器都 healthy（约 2 分钟），打开 <http://localhost:3001>
