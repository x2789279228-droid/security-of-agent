## 写在前面

这个仓库是**一个完整的安全运营平台**，不是 demo、不是论文截图。

它把安全审计的 9 件事串成了一条流水线：

```
日志接入 → 校验 / 认证 → 异常评分 → 攻击链 CEP → LLM 深度审计
        → 独立监督 CAD  →  响应编排  →  真实执行  →  复盘与反馈
```

每一件事都有**可运行的代码、可点开的前端页面、可注入数据的模拟器**。

> **理解这个项目的最好方式**：先跑起来，再回头读这套文档。
>
> ```bash
> # 在仓库根目录
> docker compose up -d --build
> docker exec soc-flink-jobmanager /opt/flink/submit-jobs.sh flink-jobmanager
> python log_simulator.py --kafka localhost:9094 --mode chain
> ```
>
> 打开浏览器：
> - 前端        <http://localhost:3001>
> - 后端        <http://localhost:8001/docs>
> - Kafka UI    <http://localhost:18082>
> - Flink 面板  <http://localhost:3002>
>
> 跑通一遍再回来看文档，你会有"哦原来那段代码是在干这件事"的连接感。

## 关键概念速查

> 第一次读到术语时回头看一眼；写代码时回头对一眼。

| 概念 | 一句话 | 出现位置 |
| :--- | :--- | :--- |
| **Kafka Topic** | 事件流转的"管道"，7 个分级 topic | [02 数据流] |
| **Flink 作业** | 跑在集群上的 Java 流处理 | [04 Flink 作业] |
| **CEP 攻击链** | 模式匹配：扫描→爆破→C2 这种顺序事件 | [04 Flink 作业] |
| **Audit-LLM** | 4 层 LLM 流水线：拆解→拼工具→执行→复核 | [03 后端模块] |
| **CAD** | 独立监督 Agent，验证 LLM 是不是在"胡扯" | [03] / [05] |
| **Sigma 规则** | YAML 写的"如果…就…"检测规则 | [03 后端模块] |
| **RAG** | 用 MITRE / CAPEC 知识库给 LLM 补背景 | [03 后端模块] |
| **响应引擎** | 真正去开防火墙、封 IP 的执行层 | [03 后端模块] |
| **MCP Guard** | 4 层检查：白名单 → 权限 → 参数 → 策略 | [05 自审计] |
| **Stabilizer** | 把 LLM 的"脏"输出修成干净的工具调用 | [05 自审计] |
| **Grounding** | 反幻觉：3 层证据校验 | [05 自审计] |
| **trace_id** | 贯穿全链路的"案卷号"，每条事件都有 | [02 数据流] |
