## 一句话定位

**一个端到端的安全运营平台**：

```
日志接入 → 校验 / 认证 → 异常评分 → 攻击链 CEP → LLM 深度审计
        →  独立监督 CAD  →  响应编排  →  真实执行  →  复盘反馈
```

所有环节跑在 Docker 化的 **Kafka + Flink + FastAPI + React** 集群上，**一键 `docker compose up` 即可启动**。

---

## 它和别的 SOC 平台有什么不一样

| 维度 | 传统 SIEM | 单 LLM Agent | **本平台** |
| :--- | :---: | :---: | :---: |
| 实时流处理 | ✅ 强 | ❌ | ✅ Kafka + Flink，秒级 |
| LLM 审计 | ❌ | ✅ 但易幻觉 | ✅ **4 层流水线 + CAD 监督** |
| 工具调用安全 | N/A | ⚠️ 无 | ✅ **MCP Guard 4 闸** |
| 真实响应 | ⚠️ 半自动 | ⚠️ 单次 | ✅ 编排 + 审批 + **回滚** |
| 自我审计 | ❌ | ❌ | ✅ **5 道闸 + 熔断器** |
| 一键跑通 | ⚠️ 重型 | ✅ | ✅ `docker compose up` |

> 一句话：**别人让 LLM 自己审自己，我们让 4 个 Agent 互相审 + CAD 独立审 + 5 道闸挡危险**。

## 最有差异化的 5 件事

> 评委常问、也是这个项目**最值得讲**的 5 件事。

| # | 亮点 | 一句话 |
| :-: | :--- | :--- |
| 1 | **Flink 唯一事实源** | 所有校验 / 打分 / CEP 在 Flink 一处完成，Python 不重算 → 单一可信源 |
| 2 | **Audit-LLM 4 层流水线** | 拆解 → 拼工具 → 执行 → 复核，每层都有产物可校验 |
| 3 | **CAD 独立监督** | 不信 LLM 汇报，自己去 PG / Qdrant 反查每条 claim |
| 4 | **MCP Guard 4 闸** | 工具调用前：白名单 → RBAC → 参数校验 → 规则引擎 |
| 5 | **响应 8 策略 × 5 动作 + TTL** | 自动封禁带 TTL 过期回滚，避免"永久误封"事故 |

## 一条事件的完整旅程

> 追一条 **"192.168.1.100 触发 50 次 SSH 失败"** 的全过程。

```
① syslog-agent ──推送──▶ Kafka security-logs-raw
② Flink Job1 (LogValidation)
   · 解析 → 校验 → API Key 认证 → 标准化 → 60s 去重
   · 通过 → security-logs-validated
   · 失败 → security-logs-rejected（带原因）
③ Flink Job2 (AnomalyDetection)
   · 5min 50 次 → 频率分 +0.3
   · high 严重度 → +0.6
   · 0-5 点 → +0.4
   · 综合分 = 1.0（封顶）
   · 命中 CEP "port_scan_to_c2" 前两步
④ Backend 消费 enriched + alerts
   · 入库 security_events（anomaly_score=1.0）
   · 推 SSE 到前端
   · 触发 Audit-LLM 4 层流水线
⑤ Audit-LLM 4 层
   · Decomposer → 拆解为子问题
   · ToolBuilder → 决定调 RAG + Sigma + 资产
   · Executor → 实际查（经 Stabilizer + Guard）
   · Reviewer → 复盘，输出 final_verdict
⑥ CAD 监督
   · 对 evidence_trail 每条 claim 反查
   · 算 hallucination_risk
   · 写 cad_reports
⑦ 响应引擎
   · 策略匹配 "auto_block_brute_force" → 封禁 1h
   · SecurityGuard 4 维审查通过
   · SSH 真实执行 iptables -I INPUT -s 192.168.1.100 -j DROP
   · TTL Manager 登记 1h 后自动解封
⑧ 复盘与反馈
   · 写 response_logs（含 rollback_token）
   · Post-Mortem 时间线重建
   · 30 天后归档
```

**全链路 `trace_id` 贯穿**：可在 Jaeger / Tempo 看到每一跳。
