## 1. 架构差异

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 检索策略 | 2 个：vector（pgvector cosine / Qdrant dense） + filter（LIKE） | 5 个：vector / bm25 / rrf / rrf_rerank / filter |
| 召回 | 单通道 dense 检索 | 双通道 dense + BM25 (sparse) → RRF 融合 |
| 查询变换 | 无 | 规则扩展（CVE / ATT&CK / hash / IP 别名）+ 可选 LLM rewrite / HyDE |
| 重排 | 无 | Cross-encoder HTTP（bge-reranker-v2-m3）→ 词法特征分 → LLM list-rerank |
| 精确召回 | 依赖 `ilike` 单条匹配 | 规则提取的 needle（CVE / T-ID / hash）注入到结果最前 |
| CJK 支持 | 整段 `ilike` | bigram 切词 + 别名词典 |
| 数据层 | 无 | `search_lex`（预切词）+ `search_tsv`（Postgres generated tsvector + GIN 索引） |
| Qdrant | 单向量 | `*_v2` collection，dense + sparse（BM25 + IDF modifier）共索引 |

新文件清单：
- `backend/rag/lexical.py`（词法原语：tokenize / encode_sparse / rrf_fuse / lexical_needles / expand_query_text）
- `backend/rag/query_transform.py`（transform_query：规则 + 可选 LLM rewrite / HyDE）
- `backend/rag/reranker.py`（HTTP cross-encoder / 词法特征 / LLM list-rerank 降级链）
- `backend/migrate_qdrant_hybrid.py`（Qdrant hybrid collection 迁移脚本）
- `backend/prompts/rag/{hyde,hyde_system,query_rewrite,query_rewrite_system}.j2`
- `backend/tests/test_rag_hybrid.py`（16 个单测，覆盖原语）

## 3. 算法对比（in-memory 评估）

**评估脚本**：`.tmp_rag_eval.py`
**环境**：SQLite `:memory:` + 30 条 SOC chunks（与 `seeder.py` 同主题分布）+ 16 条黄金查询
**向量化**：用 64 维 numpy 模拟 embedding（无关 LLM/embedding 服务）
**保证公平**：OLD 与 NEW 共用同一组 ground-truth 向量；`_vector_search` 在两者上替换为 Python cosine（无 pgvector / Qdrant 依赖）

### 3.1 总体指标（top_k=5）

| 指标 | OLD（vector+filter） | NEW（hybrid+RRF） | Δ |
|------|---------------------|------------------|---|
| recall@3 | 49.0 | **92.7** | **+43.7** |
| recall@5 | 65.6 | **97.9** | **+32.3** |
| MRR | 72.4 | **100.0** | **+27.6** |
| nDCG@5 | 58.7 | **93.5** | **+34.8** |
| top1 accuracy | 31.2 | **68.8** | **+37.6** |

### 3.2 按 query 类别拆分（recall@5）

| 类别 | n | OLD | NEW | Δ |
|------|---|---|---|---|
| cve_exact（CVE 全名） | 1 | 33.3 | 100.0 | +66.7 |
| cve_alias（CVE 俗称 → 编号） | 1 | 100.0 | 100.0 | 0.0 |
| t_id_exact（T-ID 完整） | 3 | 66.7 | 100.0 | +33.3 |
| cjk_natural（中文自然查询） | 5 | 53.3 | 100.0 | +46.7 |
| en_natural（英文自然查询） | 2 | 75.0 | 100.0 | +25.0 |
| alias_chain（"供应链 log4j 漏洞"） | 1 | 66.7 | 100.0 | +33.3 |
| t_id_alias（"phishing T1566"） | 1 | 100.0 | 100.0 | 0.0 |
| cjk_short（极短中文） | 2 | 66.7 | 83.3 | +16.6 |

**观察**：
- CVE 精确查询（"CVE-2021-44228 log4j 远程代码执行"）在 OLD 里 top1 落到 `web-sqli`（纯 dense 邻居离 log4j 主题更近），NEW 靠 `lexical_needles` 把 `log4shell-doc` 顶到第一
- 中文短查询（"横向移动检测"）OLD 拉到 `c2-beacon` 这种偏 dense 主题，NEW 靠 CJK bigram 把 `lateral-move` 系列召回

### 3.3 Ablation：hybrid off vs hybrid on（同一 NEW 管道，仅切换 `rag_hybrid_enabled`）

| 指标 | NEW dense only | NEW hybrid+RRF | Δ |
|------|----------------|----------------|---|
| recall@3 | 58.3 | 92.7 | +34.4 |
| recall@5 | 77.1 | 97.9 | +20.8 |
| MRR | 78.3 | 100.0 | +21.7 |
| nDCG@5 | 65.3 | 93.7 | +28.4 |

**解读**：即使禁用 hybrid，光是新管道的 query_transform（规则扩展 + exact-term 注入）也把 MRR 从 72.4 提到 78.3（+5.9）。打开 hybrid 后再 +21.7。所以本次改造的**质量贡献 ≈ 1/3 来自查询变换、2/3 来自 hybrid + RRF**。

## 4. 延迟对比

**评估脚本**：`.tmp_rag_latency.py`
**方法**：3 轮 × 16 查询，取中位数；top_k=5；64 维向量；新旧共用同一 Python cosine

| 配置 | p50 | p95 | avg |
|------|-----|-----|-----|
| OLD（vector+filter） | 1.9 ms | 2.2 ms | 2.0 ms |
| NEW（hybrid+RRF 满载） | 6.3 ms | 10.2 ms | 6.7 ms |
| NEW（hybrid off，dense only） | 1.9 ms | 2.4 ms | 1.9 ms |

**开销**：p50 +4.4ms / p95 +8.0ms。开销来自 BM25 通道、RRF 融合、exact-term 注入、特征重排（HTTP rerank 这次没开，开了会再 +10-50ms）。

**Rerank 路径实测参考**（`backend/rag/reranker.py:17`）：CPU BGE-reranker-v2-m3 / 20 docs 冷启动 2-8s，已设 `CE_TIMEOUT=15.0`（避免 0.8s 默认超时全失败）。

## 5. 已知边界 / 风险

1. **Qdrant v2 collection 重建**：旧 `soc_knowledge_chunks` 数据需要回填 BM25 sparse 向量，迁移脚本 `backend/migrate_qdrant_hybrid.py` 负责此过程；上线前必须先跑一次。
2. **rerank URL 误配**：`rag_rerank_url=""` 时不回落 LLM 网关（之前会打 15s 超时），但需要部署 `soc-bge-rerank`（Infinity `/rerank` 端点）才能发挥交叉编码器效果。
3. **审计 skip_llm 路径**：`_drop_unapproved` 之外的查询会走 query_transform，审计场景下默认 `skip_llm=True` 不打 LLM，但 LLM 路径本身增加 100-500ms 延迟预算。
4. **CJK bigram 召回粒度**：2-gram 命中"横向""移动"会同时命中"横向扩展"这种无关词，目前靠 `lexical_overlap_rank` + `feature_rerank` 加权缓解，未做 stopword 过滤。
